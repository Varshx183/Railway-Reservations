## What the suite verifies

- Forty concurrent database booking requests competing for 18 AC seats: 18 successes, 22 capacity rejections, unique PNRs and seat assignments.
- Twenty-four bookings through the TCP client/server: 18 successes and six capacity rejections.
- AC/sleeper coach boundaries, stored full names, invalid input, failure rollback, socket limits, EOF, and shutdown.
- Registration/login, salted password hashing, hashed sessions, logout, expired sessions, duplicate emails, and authentication throttling.
- Ticket ownership: another account cannot view or cancel a ticket; legacy TCP lookup cannot bypass ownership.
- CSRF/custom-header/content-type checks and oversized HTTP request rejection.
- Cancellation restores capacity and retains history; repeated cancellation cannot release replacement passengers' seats.
- Free seats in the middle of a coach are reused without moving other passengers.
- Concurrent cancellation, cancellation/booking races, and duplicate booking retries preserve inventory consistency.
- Date-filtered route search and available direct-train capacity.
- A real repaired-v1-to-v2 migration preserves existing tickets and remains repeatable.

## Packaged application

The actual v2 JAR passed ten CLI/HTTP smoke checks: demo initialization, web server startup, registration, login, dated search/availability, owned booking, duplicate-request retry, cancellation, ticket history, and logout. See [WEB_SMOKE_TEST.json](WEB_SMOKE_TEST.json).

Frontend JavaScript passed `node --check`. Static checks verified that JavaScript-referenced form/control IDs exist in the HTML. Docker Compose configuration passed `docker compose --env-file .env.example config --quiet`.

## Verification limits

- Browser visual/interactions verification was not completed: the browser security policy declined access to the local preview. No screenshot or successful manual browser walkthrough is claimed.
- Docker image build/startup was not tested because this machine's Docker engine was unavailable; database/application verification used a local PostgreSQL runtime and the actual JAR.
- GitHub Actions is configured but has not executed on GitHub.
- Passing tests cover the cases described here; they do not guarantee every environment/input is error-free or establish production scale.
